A network is a stack of simple functions, tuned automatically until it does a job well

Everything below unpacks that sentence. Each level builds on the last; tick “Mark done” to track progress in the bar above (saved in this browser only).

  1. Read the intuition. If you can't explain it in two sentences, reread.
  2. Turn the knobs on the level's instrument until the behaviour stops surprising you.
  3. Work the maths on paper, then type the code yourself and break it on purpose.
  4. Answer the self-check before opening it.

Level 0

A network learns rules from examples instead of being given them

Show it thousands of (input, correct answer) pairs and it adjusts millions of internal numbers until its answers match. Picture a mixing desk with a million knobs: play a song, compare the output with the target recording, nudge every knob slightly in the direction that sounds closer, repeat a million times. That is training; the knobs are the weights. The trainer at the top of this page is doing exactly that with about 700 knobs.

Five words you need from day one

  • Neuron: multiplies each input by a weight, adds them, adds a bias, squashes the result with an activation function.
  • Layer: many neurons side by side reading the same inputs.
  • Parameters: the weights and biases, the knobs. Large language models have billions.
  • Loss: one number for how wrong the network is. Training makes it small.
  • Gradient: for every knob, which way to turn it, and how strongly, to reduce the loss.

Why stacking layers works. Each layer re-describes its input more usefully. In an image model, early layers find edges, later ones textures, then eyes and wheels, then “cat” or “car”. Nobody programs these features; they emerge because they reduce the loss.

What it is not. Not a brain simulation (the analogy is loose), not understanding in a human sense, and not magic: bad or scarce data gives confident wrong answers.

It makes a prediction, measures how wrong it is with a loss, and nudges each of its numbers in the direction that reduces that error. Repeating this over many examples gradually tunes the numbers into a function that fits the data.
Level 1

Four pieces of maths carry you to Level 10

1. The dot product

Multiply matching entries, add them up. It is the operation inside every neuron and is large when two vectors point the same way, so a neuron's weights act as a pattern the input is matched against.

w·x = Σ wᵢxᵢ [0.5, −1, 2]·[2, 0, 1] = 1 + 0 + 2 = 3

2. Matrix multiplication is many dot products at once

A layer of 4 neurons reading 3 inputs stores a (3, 4) weight matrix. A batch X of shape (N, 3) times W gives (N, 4): every example against every neuron in one operation, which is what GPUs are built for. Shape rule: (a, b) @ (b, c) → (a, c). Most beginner bugs are shape bugs.

3. Derivatives and the chain rule

A derivative says how fast an output changes when you wiggle an input; the gradient lists that for every parameter and points uphill, so training steps the other way. A network is functions inside functions, and the chain rule multiplies local derivatives along the path:

dy/dx = dy/dg · dg/dx y = (3x + 1)² → g = 3x + 1, dy/dg = 2g, dg/dx = 3 → dy/dx = 6(3x + 1)

Backpropagation (Level 4) is this rule applied layer by layer.

4. Probability

Softmax turns scores (logits) into probabilities: exponentiate, divide by the sum. If the model gives the correct class probability p, the loss −ln p is 0 at p = 1 and huge near 0: that is cross-entropy. Visual refresher: 3Blue1Brown's “Essence of Linear Algebra” and “Essence of Calculus”.

Level 2

A neuron is a weighted vote passed through a bend

Should I go running?

z = w·x + b a = f(z)

The weights say how much each input matters and in which direction; the bias shifts how easily the neuron fires. With the defaults, tiredness carries a large negative weight and wins: z = −0.6, so σ(−0.6) ≈ 0.35. Drag “Tired” to 0 and watch it flip.

Why the activation matters

Without a non-linear activation, layers collapse: a linear function of a linear function is linear, so 100 layers equal one. Try “No activation” in the trainer at the top: it can only draw a straight line through the spirals.

One neuron is logistic regression: a single sigmoid neuron trained with cross-entropy draws one straight boundary. A network is, roughly, many of these stacked. Its limit is XOR (output 1 when exactly one input is 1): no single line separates those points, which stalled the field after 1969. A hidden layer fixes it.

Level 3

Hidden layers re-map inputs until the problem becomes easy

A multi-layer perceptron (MLP) chains layers; running an input through all of them is the forward pass. “Deep” just means many hidden layers.

h⁽¹⁾ = f(X W⁽¹⁾ + b⁽¹⁾) h⁽²⁾ = f(h⁽¹⁾ W⁽²⁾ + b⁽²⁾) ŷ = softmax(h⁽²⁾ W⁽³⁾ + b⁽³⁾)

Why it works, and what to pick

The universal approximation theorem says one hidden layer with enough neurons can approximate any continuous function on a bounded region; each ReLU adds a bend. But “enough” can be enormous, and in practice depth beats width because deep networks reuse features. Tabular data: 2–4 layers of 64–512 units (and compare against gradient-boosted trees). Images, audio and text: use the architectures of Levels 8–10.

Level 4

Learning is four steps on repeat: forward, loss, backprop, update

1. The loss

TaskOutput layerLoss
RegressionLinearMean squared error ½(ŷ − y)²

2. Gradient descent

Blindfolded on a hillside, feel the slope and step downhill. η, the learning rate, is the most important hyperparameter. Mini-batches of 32–4096 examples per step are the standard (“SGD” usually means this); one pass through the data is an epoch.

w ← w − η · ∂L/∂w

Loss L(w) = (w − 2)² + 1, starting at w = −3. Find the learning rate where it starts zig-zagging, and where it explodes.

3. Backpropagation

Backprop gets the gradient for every weight in one backward sweep: each operation receives “how much the loss changes per unit of my output”, multiplies by its local derivative, and passes it on. It costs about two forward passes however many weights there are.

dZ = dA ⊙ f′(Z) dW = A_prevᵀ dZ db = Σ_rows dZ dA_prev = dZ Wᵀ softmax + cross-entropy: dZ = p − y

Vanishing and exploding gradients. Backprop multiplies many local derivatives. Sigmoid's is at most 0.25, so ten sigmoid layers can shrink a gradient by about 10⁻⁶. ReLU, careful initialization, normalization, residual connections and clipping (Level 6) are why deep learning took off after about 2010.

Backprop, one line at a time

x → sigmoid neuron (w₁, b₁) → linear output (w₂, b₂), loss ½(y − t)². Edit the start values, step through, then apply the update and go again.

Self-check: redo the example with t = 0. What is ∂L/∂w₁?
∂L/∂y = 1.2449, ∂L/∂h = 2.4898, ∂L/∂w₁ ≈ 0.5851. Set t = 0 above to confirm. For softmax + cross-entropy, differentiating −ln(softmax) gives ∂L/∂zᵢ = pᵢ − yᵢ.
Level 5

Build one from scratch once, and it stops being magic

About 100 lines of NumPy: forward pass, backprop, Adam, a gradient check and mini-batch training on two spirals. Run while writing this playbook: the gradient check gives a relative error of 6×10⁻¹¹ and test accuracy reaches 100% within 200 epochs, in under a second on a CPU. Type it rather than paste it.

Read the code against the maths

  • forward caches every z and a for the backward pass; that memory is why training needs far more GPU memory than inference.
  • delta[np.arange(n), y] -= 1 is the dZ = p − y shortcut.
  • a_prev.T @ delta is dW; delta @ W.T * relu_grad passes the gradient down a layer.
  • Adam keeps running averages of gradients and squared gradients, giving every weight its own step size.
  • Gradient-check error below 1e-6 means correct backprop; above 1e-3 means a bug.

import numpy as np

# ---------- 1. Data: two interleaved spirals (not linearly separable) ----------
def make_spirals(n=200, noise=0.2, seed=0):
    rng = np.random.default_rng(seed)
    theta = np.sqrt(rng.random(n)) * 3 * np.pi
    a = np.c_[theta * np.cos(theta), theta * np.sin(theta)]
    b = -a
    X = np.r_[a, b] + rng.normal(0, noise, (2 * n, 2))
    y = np.r_[np.zeros(n), np.ones(n)].astype(int)
    X = (X - X.mean(0)) / X.std(0)          # standardize inputs
    return X, y

# ---------- 2. Building blocks ----------
def relu(z):        return np.maximum(0, z)
def relu_grad(z):   return (z > 0).astype(z.dtype)

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)    # numerical stability
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def cross_entropy(probs, y):
    return -np.log(probs[np.arange(len(y)), y] + 1e-12).mean()

# ---------- 3. The model ----------
class MLP:
    def __init__(self, sizes, seed=0):
        rng = np.random.default_rng(seed)
        # He initialization: good default for ReLU
        self.W = [rng.normal(0, np.sqrt(2 / m), (m, n)) for m, n in zip(sizes[:-1], sizes[1:])]
        self.b = [np.zeros(n) for n in sizes[1:]]

    def forward(self, X):
        self.cache = [(None, X)]            # (pre-activation z, activation a)
        a = X
        for i, (W, b) in enumerate(zip(self.W, self.b)):
            z = a @ W + b
            a = softmax(z) if i == len(self.W) - 1 else relu(z)
            self.cache.append((z, a))
        return a

    def backward(self, y, l2=0.0):
        n = len(y)
        probs = self.cache[-1][1]
        delta = probs.copy()
        delta[np.arange(n), y] -= 1         # dL/dz for softmax + cross-entropy
        delta /= n
        gW, gb = [], []
        for i in reversed(range(len(self.W))):
            a_prev = self.cache[i][1]
            gW.insert(0, a_prev.T @ delta + l2 * self.W[i])
            gb.insert(0, delta.sum(0))
            if i > 0:
                z_prev = self.cache[i][0]
                delta = (delta @ self.W[i].T) * relu_grad(z_prev)
        return gW, gb

# ---------- 4. Adam optimizer ----------
class Adam:
    def __init__(self, params, lr=1e-2, b1=0.9, b2=0.999, eps=1e-8):
        self.lr, self.b1, self.b2, self.eps, self.t = lr, b1, b2, eps, 0
        self.m = [np.zeros_like(p) for p in params]
        self.v = [np.zeros_like(p) for p in params]

    def step(self, params, grads):
        self.t += 1
        for i, (p, g) in enumerate(zip(params, grads)):
            self.m[i] = self.b1 * self.m[i] + (1 - self.b1) * g
            self.v[i] = self.b2 * self.v[i] + (1 - self.b2) * g * g
            m_hat = self.m[i] / (1 - self.b1 ** self.t)
            v_hat = self.v[i] / (1 - self.b2 ** self.t)
            p -= self.lr * m_hat / (np.sqrt(v_hat) + self.eps)   # in-place update

# ---------- 5. Gradient check (always do this once when writing backprop) ----------
def grad_check(model, X, y, eps=1e-5):
    model.forward(X); gW, _ = model.backward(y)
    W = model.W[0]; i, j = 0, 0
    old = W[i, j]
    W[i, j] = old + eps; lp = cross_entropy(model.forward(X), y)
    W[i, j] = old - eps; lm = cross_entropy(model.forward(X), y)
    W[i, j] = old
    num = (lp - lm) / (2 * eps)
    return abs(num - gW[0][i, j]) / max(1e-12, abs(num) + abs(gW[0][i, j]))

# ---------- 6. Train ----------
X, y = make_spirals()
rng = np.random.default_rng(1)
idx = rng.permutation(len(X)); split = int(0.8 * len(X))
Xtr, ytr, Xte, yte = X[idx[:split]], y[idx[:split]], X[idx[split:]], y[idx[split:]]

model = MLP([2, 64, 64, 2])
print("gradient check relative error:", grad_check(model, Xtr[:20], ytr[:20]))
opt = Adam(model.W + model.b, lr=1e-2)

for epoch in range(1, 501):
    perm = rng.permutation(len(Xtr))
    for k in range(0, len(Xtr), 32):                      # mini-batches of 32
        bi = perm[k:k + 32]
        model.forward(Xtr[bi])
        gW, gb = model.backward(ytr[bi], l2=1e-4)
        opt.step(model.W + model.b, gW + gb)
    if epoch % 100 == 0:
        p_tr = model.forward(Xtr); loss = cross_entropy(p_tr, ytr)
        acc_tr = (p_tr.argmax(1) == ytr).mean()
        acc_te = (model.forward(Xte).argmax(1) == yte).mean()
        print(f"epoch {epoch:3d}  loss {loss:.4f}  train acc {acc_tr:.3f}  test acc {acc_te:.3f}")
Level 6

Most of deep learning is making training work reliably

Data first

Split train / validation / test (e.g. 80/10/10) and touch test once. Standardize inputs with training-set statistics only. Check 100 random labels by hand. Augment: flips, crops and colour jitter for images; noise and shifts for audio.

Initialization and optimizers

ChoiceRule
He init (ReLU)std = √(2 / fan_in)
Xavier init (tanh, sigmoid)std = √(2 / (fan_in + fan_out))
SGD + momentum 0.9Vision; often generalizes best with a good schedule
Adam, lr 1e-3Default starting point
AdamWAdam with decoupled weight decay; default for Transformers

Schedules matter as much as optimizers: linear warmup for 1–5% of steps, then cosine decay to about 10% of peak. Find the peak with a learning-rate range test. Scaling batch size by k: scale lr by roughly k or √k.

Regularization, normalization, stability

  • Weight decay 0.01–0.1 with AdamW; dropout 0.1–0.5, off at inference; early stopping; label smoothing; more data and augmentation are the strongest of all.
  • BatchNorm for CNNs (train/eval modes differ, a classic bug); LayerNorm or the cheaper RMSNorm for Transformers.
  • Residual connections (x + F(x)) give gradients a highway and made 100+ layer networks trainable.
  • Gradient clipping at norm 1.0 for RNNs and Transformers; bf16 mixed precision for about 2× speed and half the memory.

Level 7

PyTorch does Levels 4 to 6 for you, on a GPU

It records operations on tensors and computes all gradients automatically (autograd), runs on GPUs and ships layers, losses and optimizers. It dominates research and most industry work; JAX is the main alternative.

  • Tensor: a NumPy array that can live on a GPU and track gradients.
  • Autograd: loss.backward() fills .grad on every parameter.
  • nn.Module: a class holding parameters and a forward method.
import torch
w = torch.tensor(2.0, requires_grad=True)
loss = (3 * w + 1) ** 2
loss.backward()
print(w.grad)   # tensor(42.) = 6 * (3*2 + 1), the Level 1 chain-rule example

The training-loop template: an MLP on MNIST digits, typically about 97–98% test accuracy after five epochs on a laptop CPU.

import torch, torch.nn as nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

device = "cuda" if torch.cuda.is_available() else "cpu"

tfm = transforms.Compose([transforms.ToTensor(), transforms.Normalize((0.1307,), (0.3081,))])
train_ds = datasets.MNIST("data", train=True, download=True, transform=tfm)
test_ds  = datasets.MNIST("data", train=False, download=True, transform=tfm)
train_dl = DataLoader(train_ds, batch_size=128, shuffle=True)
test_dl  = DataLoader(test_ds, batch_size=512)

model = nn.Sequential(
    nn.Flatten(),
    nn.Linear(784, 256), nn.ReLU(), nn.Dropout(0.2),
    nn.Linear(256, 128), nn.ReLU(),
    nn.Linear(128, 10),            # raw logits: CrossEntropyLoss applies softmax itself
).to(device)

loss_fn = nn.CrossEntropyLoss()
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

for epoch in range(5):
    model.train()                                  # enables dropout / batchnorm training mode
    for xb, yb in train_dl:
        xb, yb = xb.to(device), yb.to(device)
        logits = model(xb)                         # 1. forward
        loss = loss_fn(logits, yb)                 # 2. loss
        opt.zero_grad()                            # 3a. clear old gradients
        loss.backward()                            # 3b. backprop
        opt.step()                                 # 4. update

    model.eval()                                   # disables dropout
    correct = 0
    with torch.no_grad():                          # no graph needed for evaluation
        for xb, yb in test_dl:
            xb, yb = xb.to(device), yb.to(device)
            correct += (model(xb).argmax(1) == yb).sum().item()
    print(f"epoch {epoch}  last batch loss {loss.item():.3f}  test acc {correct / len(test_ds):.4f}")

torch.save(model.state_dict(), "mnist_mlp.pt")

A 224×224 colour image is 150,528 numbers; one dense layer of 1,000 units would need 150 million weights and would learn “edge” separately at every position. A 3×3 conv filter has 27 weights and finds edges everywhere. CNNs build in locality and translation equivariance.

output = ⌊(W − K + 2P) / S⌋ + 1 params = K·K·C_in·C_out + C_out

Each filter makes one feature map; stride 2 or 2×2 max-pooling halves resolution; padding 1 keeps a 3×3 conv's size. Stacked layers see ever larger regions (the receptive field), giving the edges → textures → parts → objects hierarchy.

import torch.nn as nn

def block(c_in, c_out):
    return nn.Sequential(
        nn.Conv2d(c_in, c_out, 3, padding=1), nn.BatchNorm2d(c_out), nn.ReLU(),
        nn.Conv2d(c_out, c_out, 3, padding=1), nn.BatchNorm2d(c_out), nn.ReLU(),
        nn.MaxPool2d(2),
    )

model = nn.Sequential(          # CIFAR-10: 32x32 colour images, 10 classes
    block(3, 32),     # 32x32 -> 16x16
    block(32, 64),    # 16x16 -> 8x8
    block(64, 128),   # 8x8   -> 4x4
    nn.Flatten(),     # 128 * 4 * 4 = 2048
    nn.Dropout(0.3),
    nn.Linear(2048, 10),
)

With crop and flip augmentation, about 85% is a realistic target after 20–30 epochs; a well-tuned ResNet-18 reaches 93–95%.

Level 9

Sequences moved from step-by-step memory to looking at everything at once

Text is split into tokens, each mapped by an embedding table to a learned vector; words in similar contexts get similar vectors (king − man + woman ≈ queen).

RNNs

hₜ = tanh(Wₓ xₜ + W_h hₜ₋₁ + b)

The same weights run at every step, carrying a memory h. Training unrolls the loop (backpropagation through time), and over 50+ steps gradients vanish or explode, so plain RNNs forget the start of long sentences.

LSTM and GRU

The LSTM (1997) adds a cell state updated by addition and three sigmoid gates: forget what to erase, input what to write, output what to expose. Gradients survive hundreds of steps. The GRU is a simpler two-gate variant. LSTMs powered translation and speech recognition from about 2014 to 2018.

import torch.nn as nn
class SentimentLSTM(nn.Module):
    def __init__(self, vocab, d=128, h=256):
        super().__init__()
        self.emb = nn.Embedding(vocab, d)
        self.lstm = nn.LSTM(d, h, batch_first=True)
        self.head = nn.Linear(h, 2)
    def forward(self, ids):              # ids: (N, T) integer tokens
        out, (h_n, c_n) = self.lstm(self.emb(ids))
        return self.head(h_n[-1])         # final hidden state -> 2 classes

Attention

Encoder–decoder RNNs squeezed a sentence into one vector. Attention (2014) lets each output step take a weighted average of all input states, weighted by relevance. The general form is a soft dictionary lookup: compare a query with every key, softmax the scores, average the values. √d_k keeps scores from saturating the softmax. In 2017 “Attention Is All You Need” dropped recurrence entirely: the Transformer trains in parallel over the whole sequence.

Attention(Q, K, V) = softmax(QKᵀ / √d_k) V

RNN-style models survive in streaming and on-device work; state-space models (S4, Mamba) compete with Transformers on very long sequences.

Softmax and temperature

Query “it” scores three keys. Values are 10, 20, 30. Lower temperature sharpens attention; higher spreads it.

–weighted value Σ pᵢ·vᵢ

Level 10

Every major LLM is a large Transformer trained to predict the next token

Causal self-attention

Each row is one token's attention over the sentence. Random, untrained weights: the pattern is meaningless, the mechanics are real. Click a row.

Size and memory estimator

–≈ 12·L·d² params
–weights in memory
–full fine-tune, AdamW

Rules of thumb: training compute ≈ 6 · params · tokens FLOPs; full fine-tuning with AdamW in mixed precision needs about 16 bytes per parameter before activations. KV cache comes on top for inference.

In self-attention queries, keys and values come from the same sequence; a causal mask hides future tokens so next-token prediction is honest. This runs as written:

import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

def causal_self_attention(X, Wq, Wk, Wv):
    """X: (T, d_model). Returns (T, d_head) and the (T, T) attention weights."""
    Q, K, V = X @ Wq, X @ Wk, X @ Wv                 # each (T, d_head)
    scores = Q @ K.T / np.sqrt(K.shape[-1])          # (T, T): how much token i attends to j
    mask = np.triu(np.ones_like(scores), k=1)        # 1 above the diagonal = the future
    scores = np.where(mask == 1, -np.inf, scores)    # a token may not look ahead
    weights = softmax(scores, axis=-1)               # each row sums to 1
    return weights @ V, weights

rng = np.random.default_rng(0)
T, d_model, d_head = 4, 8, 4
X = rng.normal(size=(T, d_model))
Wq, Wk, Wv = (rng.normal(size=(d_model, d_head)) / np.sqrt(d_model) for _ in range(3))
out, w = causal_self_attention(X, Wq, Wk, Wv)
print(out.shape)          # (4, 4)
print(np.round(w, 2))     # lower-triangular; row sums = 1

The block

  • Multi-head attention: h heads in parallel, each learning different relations, concatenated and projected.
  • Feed-forward MLP: expand to about 4× d_model with GELU/SiLU (often SwiGLU); much of the knowledge lives here.
  • Pre-norm residuals: x = x + Attn(Norm(x)); x = x + MLP(Norm(x)).
  • Position: learned or sinusoidal embeddings early on, RoPE in most current LLMs.

How an LLM is made and used

  1. Tokenize with byte-pair encoding (~50k–200k tokens).
  2. Pretrain on trillions of tokens; nearly all capability and compute is here.
  3. Supervised fine-tuning on instruction–response pairs.
  4. Preference and RL: RLHF, DPO, and reinforcement learning on checkable tasks (maths, code) that teaches longer reasoning.

Generation samples one token at a time. Temperature and top-p control randomness; the KV cache stores past keys and values so each new token is cheap, and is the main memory limit for long contexts. Chinchilla (2022) found compute-optimal training near 20 tokens per parameter; today's models train far past that because smaller models are cheaper to serve. Build one: Karpathy's “Let's build GPT” and nanoGPT.

Self-check: why does a decoder need a causal mask but BERT does not? bf16 weight memory of a 70B model?
A decoder generates left to right, so seeing the future would be cheating; BERT fills blanks using both sides. 70B × 2 bytes ≈ 140 GB.

Diffusion in a paragraph: add noise to real images over many steps until they are static; train a network to predict the added noise; to generate, start from static and repeatedly remove the predicted noise. Conditioning on text embeddings gives text-to-image.

Self-supervised and multimodal

Invent the task from the data: predict the next token, fill masked patches, or pull matching pairs together (contrastive learning). CLIP aligns images and captions, enabling zero-shot classification and vision-language models.

Scaling, interpretability, open puzzles

  • Scaling laws: loss falls as a smooth power law in parameters, data and compute. Mixture of Experts routes each token to 1–2 of many MLPs. Large runs combine data, FSDP/ZeRO, tensor and pipeline parallelism.
  • Interpretability: probing, attribution, and mechanistic work such as induction heads and sparse autoencoders that split activations into readable features.
  • Puzzles: double descent, the lottery ticket hypothesis, grokking, the neural tangent kernel, emergence versus metric artifacts.
  • Other branches: graph neural networks, deep RL (DQN, PPO, AlphaZero), science (AlphaFold, weather models).

Read papers: abstract → figures → conclusion, then method. Re-implement the core in under 200 lines on a toy problem. One paper a week, one re-implementation a month.

Adapting big models cheaply

Level 12

A trained model is a fifth of a working ML system; the rest is platform work

The lifecycle

  1. Data: versioned (DVC, lakeFS, immutable snapshots) and validated.
  2. Experiments: code commit, config, metrics, artifacts per run (MLflow, W&B).
  3. Registry: staging → production with metrics attached.
  4. Packaging: TorchScript, ONNX or safetensors in an image with pinned CUDA.
  5. Serving: API with batching, autoscaling, health checks.
  6. Monitoring: system and model metrics, drift alerts.
  7. Retraining through the same pipeline (Kubeflow, Argo Workflows, Airflow).

GPUs on Kubernetes

  • NVIDIA GPU Operator: drivers, device plugin, DCGM; pods request nvidia.com/gpu: 1.
  • Sharing: MIG slices with isolation; time-slicing without.
  • Autoscaling: CPU-based HPA is wrong for GPU inference. Scale on queue depth, in-flight requests or GPU utilization; KEDA fits, including scale-to-zero, but loading a 14 GB model takes tens of seconds.
  • Scheduling: tainted GPU node pools, Kueue or Volcano for training queues, gang scheduling.
  • Weights: cache on node-local disk or a shared volume, not pulled at every pod start.
